# Helicopter Attack — Clean Rewrite Plan

> **Document status:** Proposed rewrite plan, not a current implementation specification. Compare it with the present `HelicopterPilot` code and current test evidence before executing it. Active priorities live in the [README](README.md#near-term-roadmap).

## Goal (the whole contract)
1. Pick a target + an **attack point** (best of several terrain-clear approach directions).
2. Fly **normally** (reuse existing pathfinding) to the attack point.
3. At the attack point, turn toward the target and **fly straight at it, firing**.
4. Within **break-off distance** (~300 m), stop firing and fly to a safe egress point.
5. Then resume normal mission / pick a new target.

The current system is ~70 tangled combat functions with a parallel route engine,
phase machine, takeover controller, CCIP feedback, settle gates, simplification,
etc. We replace the **flight flow AND the aim/firing** with a small, legible
state machine that reuses the helicopter's normal `set_destination()` pathfinding.

## Design: 4-state attack machine
A single enum drives everything. State stored in one var; no parallel route arrays.

```
enum AtkState { SELECT, INGRESS, RUN, EGRESS }
```

- **SELECT**: scan targets/weapons, choose target + attack point + egress point.
  Transition → INGRESS. (Throttled by existing `_combat_scan_timer_s`.)
- **INGRESS**: `set_destination(attack_point)`; let normal flight fly there.
  When within `attack_point_reach_m` (e.g. 120 m) → RUN.
- **RUN**: `set_destination(target_horizontal)` (target X/Z at the heli's current
  altitude so altitude-hold doesn't fight). Normal flight flies straight at it,
  banking to track. Each frame: run the **aim+fire** check. Exit RUN when:
    - within `breakoff_distance_m` (~300 m) of target, OR
    - velocity points away from target (overflew), OR
    - target dead / lost / timeout.
  → EGRESS.
- **EGRESS**: `set_destination(egress_point)`; fly there normally. When reached or
  far enough from target → SELECT (clear plan, resume).

Flight is ALWAYS the heli's normal `_fly_toward`/pathfinding via `set_destination`.
No combat-specific steering, no lateral-suppression, no nose-yaw override.

## Aim + fire (rewritten, simple)
During RUN only:
- Compute aim error from **aircraft centerline** to a predicted aim point
  (keep the existing `_get_combat_predicted_aim_point` / CCIP helpers — they are
  the weapon ballistics and are not the broken part).
- Pitch: a simple proportional cyclic command toward the aim point's elevation,
  fed as an additive pitch correction (small, clamped). The body already flies at
  the target, so this is fine-tuning, not the primary aiming.
- Yaw: none added — the body flies at the target, so the nose is already on it.
- Fire gate: fire when `aim_dot >= cos(fire_cone_deg)` and within `fire_range_m`.
  One cone check. No settle timers, no takeover, no fallback gate.

## Attack point selection (best of several directions)
Small helper (can live in HelicopterPilot or a trimmed AttackPlanner call):
- Candidate approach directions: 8 compass dirs + direct-from-current.
- For each: `attack_point = target - dir * ingress_dist`,
  `egress_point = target + (break-off turn to the clear side)`.
- Score by: (a) terrain-clear from current→attack_point and attack_point→target
  (reuse `_get_ground_height_at_position` sampling), (b) alignment with current
  heading (prefer less turning). Pick best.
- Reuse the EXISTING `AttackPlanner.build_air_attack_plan*` ONLY for this
  point-selection if it's clean enough; otherwise a ~40-line local helper.

## What gets deleted / retired
Remove (or stop calling) the parallel-route + phase + takeover machinery:
- `_build_combat_route_job_data`, `_append_combat_*_leg`, `_simplify_combat_route`,
  `_start/finish/cancel_combat_route_job`, `_execute_combat_route_attack`,
  `_advance_combat_route`, `_get_combat_route_carrot_point`,
  `_has_passed_combat_waypoint`, `_get_combat_route_phase`,
  `_find_combat_route_phase_index`, route vars (`_combat_route_*`).
- Takeover system: `_request/_release/_is_combat_aim_takeover_active`,
  `_apply_combat_aim_takeover_speed`, takeover exports.
- Settle system: `_update_combat_aim_settle`, `_is_combat_aim_settled_for_fire`,
  `_get_combat_*_settle_*`, `_is_combat_rocket_fallback_fire_ready`.
- The big `_get_combat_aim_commands` (replaced by the small RUN aim/fire).
- `_combat_attack_corridor_hazard_ahead`, `_should_keep_combat_attack_segment`,
  `_should_hold_combat_attack_for_first_rocket`, setup-point/lineup code.

## What gets kept (weapon plumbing — not broken)
- `_get_combat_predicted_aim_point`, `_get_combat_rocket_ccip_*`,
  `_predict_combat_ballistic_aim_point`, `_get_primary_combat_hardpoint`,
  `_get_combat_weapon_muzzle_speed`, `_get_best_combat_weapon_alignment_dot`.
- Target/weapon scanning: `_get_combat_target_candidates`, `_get_combat_weapon_options`,
  `_is_valid_combat_target`, snapshot builders.
- The firing call into hardpoints (`_try_fire_combat_rocket_salvo` simplified, or a
  direct `hardpoint.fire()` for guns).
- The AIM_SAMPLE logging (already added) — extend with the new state so we can verify.

## Integration (unchanged hook)
`_update_combat_attack(delta, transit_speed)` stays the single entry from the
LOW_LEVEL_TRANSIT branch (line ~1229). It runs the new state machine and:
- returns `true` only when it owns the frame's flight (it calls `set_destination`
  + lets the normal `_fly_toward` run — actually it can just set destination and
  return `false` to let the existing transit flight execute, OR keep returning
  `true` and call `_fly_toward` itself). **Decision: set destination + return false**
  so it uses the *identical* flight path as normal mission flying. RUN phase is the
  only one that may need to return true (to inject the pitch-aim correction) — TBD,
  prefer false everywhere if the additive pitch correction can be applied in the
  normal flight path via the existing combat-aim hook.

## Rollout / safety
- All new tunables as `@export` (reach radii, breakoff distance, fire cone, range,
  ingress distance, pitch-aim gain).
- Keep `combat_enabled` master switch.
- Build incrementally: (1) state machine + INGRESS/EGRESS flying to points using
  set_destination (verify it flies normally to the point and back), (2) RUN flying
  at target + breakoff (verify it runs in and breaks off), (3) aim+fire (verify it
  shoots). Validate each step's log before the next.
- Parse-check after each step with the local Godot console exe.
